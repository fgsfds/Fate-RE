# Restoration coordination

Use the four profiles and task packet in [RESTORATION-AGENTS.md](../../../docs/RESTORATION-AGENTS.md).
Read the selected TOML once. Configuration and explicitly requested bounded
trials do not resume a paused open-ended goal.

- Keep quick triage, packet copying, report extraction and short docs with the
  integrator. Delegate work only when independent judgment or actual overlap
  justifies its context and reporting cost. No fixed worker count.
- Use fresh bounded context and the profile's model/reasoning. Name absolute cwd,
  owned scratch, frozen inputs, question/commands, budget, output files and stop
  rule. Reply word limits do not excuse incomplete outputs; resolve ordinary
  path discovery and do not relay the same incomplete task repeatedly.
- The integrator owns shared source, registries, inventories, acceptance and
  unsigned publication. Workers write only their owned scratch. One exclusive,
  windowless DOSBox lease at a time; freeze production during gates. Stop the
  experiment when the first useful result answers its question.
- Review real C/ABI risks and verifier rejection behavior. A focused source
  review may accept with final gates pending. Report fixture stubs and scope
  precisely. Exact bytes, LE classes/sites/targets and the fresh whole image
  remain mandatory; diagnostics and old hashes do not substitute for acceptance.
- After an authorized push, give the CI monitor its exact SHA and bounded watch
  budget and expected workflow/check names. Publication follows existing user
  authorization, including for a bounded trial. Observe known live handles; timeouts are not terminal, and absent or
  pending checks are unverified. Stop monitors on pause.
- Compare effectiveness through completed outputs, elapsed work and parent
  intervention. Do not infer token savings from cheaper models, cumulative goal
  usage or a fast requalification of preserved source. Record token counters
  only when provided by the host.
